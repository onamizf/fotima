## Запуск в Windows

1. Скачать ZIP проекта с GitHub, распаковать и открыть папку, где лежит `index.html`.
2. В адресной строке Проводника ввести `cmd`, нажать Enter.
3. Выполнить `py -m http.server 8000` и оставить окно открытым.
4. В браузере того же компьютера открыть `http://localhost:8000`.

Нужен Python 3. Если команда `py` отсутствует, установить Python либо использовать установленный `python`. Зависимости сайта устанавливать не требуется.

## Запуск в Linux / облачной среде

```bash
cd /workspace/fotima
python -m http.server 8000 --bind 0.0.0.0
```

На том же компьютере открыть `http://localhost:8000`. В облачной среде нужен предпросмотр/проброс порта 8000: localhost личного компьютера не указывает на облачную машину. Для телефона в одной локальной сети можно использовать адрес компьютера с сервером и порт 8000. Публичного развёртывания нет. Открывать приложение через HTTP, а не как локальный HTML-файл: сохранение через file:// браузеры обрабатывают по-разному.

Сайт статический, без этапа сборки, API и внешних JS-библиотек. Шрифт и графика размещены локально. Лицензия Inter: `assets/OFL.txt` (SIL OFL 1.1).

## Что работает

- Навигация главная → каталог → теория → лаборатория → демонстрационный результат; история браузера и отдельные адреса каждой темы.
- Три разных урока: подготовка лабораторного стола, растворение соли, фильтрация смеси песка с водой.
- В каждом уроке — цель, три короткие части, собственная статическая схема, словарь из четырёх терминов, два вопроса с тремя вариантами.
- Объяснение каждого правильного и неправильного варианта. Ответ можно менять и проверять повторно без штрафа. До выбора ответа проверка недоступна.
- После посещения трёх частей и двух правильных проверенных ответов открывается демонстрационная лаборатория. Прямой переход не обходит эту проверку.
- Смена языка сохраняет главу, ответы и результат проверки. Русский, узбекский латиницей, узбекский кириллицей и английский содержат отдельные тексты, а не runtime-транслитерацию.
- Глава, посещённые части, выбранные ответы и объяснения после проверки восстанавливаются после перезагрузки. Повтор вопросов очищает только ответы этой темы, сохраняя прочитанные части.
- Настройки языка, звука и уменьшения движения; звук пока только настройка, эффектов нет.
- Отдельное локальное хранение результатов теории и демонстрационных отметок. **Пройти теорию не значит выполнить опыт или завершить всю тему; достижений пока нет.**
- Сброс данных приложения с подтверждением. При недоступном localStorage появляется предупреждение; в памяти текущей страницы сайт остаётся рабочим. Аккаунтов и личных данных учеников нет.

## Как проверить этап 4 вручную

1. В каталоге выбрать тему. Пройти части 1, 2 и 3, открыть словарь и «Проверь понимание».
2. Выбрать неверный вариант и нажать «Проверить ответ». Убедиться, что объяснена ошибка. Выбрать другой ответ и проверить его.
3. Правильно ответить на оба вопроса: появится отметка о прохождении теории и ссылка на демонстрационную лабораторию. Настоящий опыт не засчитывается.
4. Сменить язык и перезагрузить страницу. Глава, выбранные ответы и объяснения остаются; изменяются только тексты.
5. Нажать «Повторить вопросы». Ответы этой темы очищаются, части теории остаются доступны. Пока оба вопроса снова не зачтены, лаборатория закрыта.

## Содержание и экспертная проверка

Полный комплект текстов, терминов, вариантов и объяснений — в [LESSON_CONTENT_REVIEW.md](LESSON_CONTENT_REVIEW.md). В начале документа перечислены вопросы для преподавателя и незаполненная таблица согласования. Материалы не выдаются за цитаты из неизвестного учебника или за утверждённую школьную программу.

Исходное основание: PROJECT_BRIEF.md, SCENARIOS_AND_SITEMAP.md, ТЗ, дизайн-система и инструкция исполнителю. Необходимо сверить терминологию, возрастную уместность, правила защиты и объяснения с конкретным учебником; переводы должен вычитать компетентный проверяющий. Объёмы воды и порции соли намеренно не назначены без согласования. Внутренняя проверка кода не заменяет экспертную проверку содержания.

Данные уроков имеют версию. При содержательном изменении правил или вопросов нужно увеличить version всех языковых вариантов соответствующей темы, чтобы старые ответы не засчитывались автоматически.

## Структура

- `src/i18n.js`, `src/content.js` — интерфейс и сохранённые временные подписи каркаса.
- `src/lessons/{ru,uz-Latn,uz-Cyrl,en}.js` — отдельные предварительные тексты уроков.
- `src/lesson-state.js` — подписи учебных экранов, проверка сохранённых данных и критерии прохождения теории.
- `src/lesson-view.js` — части урока, схемы, словарь, вопросы и объяснения.
- `src/storage.js` — локальное хранение; `src/app.js` — страницы и навигация.
- `src/illustrations.js`, `src/styles.css` — рисунки и стили утверждённого дизайна.
- `design/` — согласованный прототип этапа 2; он сохранён как исторический артефакт.

## Проверки

При работающем сервере на порту 8000:

```bash
node tests/validate_lessons.cjs
python tests/lessons_e2e.py
python tests/smoke.py
```

Node нужен только для проверки структуры материалов. Для браузерных проверок в текущей среде установлены Python Playwright и системный `/usr/bin/chromium`. Они не нужны для обычного запуска сайта. На другом компьютере необходимо отдельно установить тестовые инструменты и указать локальный путь к Chromium.

Результаты текущего этапа:

- Проверка содержания: 12 языковых версий трёх уроков, 36 разделов, 24 вопроса, 72 объяснения вариантов; одинаковые идентификаторы и ключи ответов, непустые тексты.
- `artifacts/stage4-validation.json`: 36 прохождений (3 темы × 4 языка × 3 размера), 216 проверок вариантов, 252 проверки компоновки. Проверены ошибка/исправление, перезагрузка, язык, повтор, запрет обхода теории и устаревшая версия сохранённого урока. Дополнительные размеры: 320 px, альбомный экран 812 px и увеличенный текст.
- `artifacts/stage4-regression.json`: сохранение настроек и демонстрационных отметок, история, сброс, повреждённое/заблокированное хранилище, 96 компоновок страниц.
- Снимки уроков и вопросов: `artifacts/stage4-*.png`. Отчёты и снимки stage3 сохранены отдельно как история.

Все браузерные проверки — эмуляция в Chromium. Реальные телефоны, Safari, Firefox, полноценный аудит доступности и апробация с учениками ещё не проверены.

## Ограничения

Лаборатория и результат всё ещё демонстрационные: нет настоящего растворения, фильтрации, дозирования, сборки установки и достижений. Эти функции относятся к этапам 5–7. Сохранение только в том же браузере, устройстве и адресе сайта; очистка браузерных данных удаляет прогресс. Нет облачной синхронизации и персональных аккаунтов.

Ключ `fotima.chemistry7.shell.v1` сохраняет совместимость с этапом 3: прежние настройки и демонстрационные отметки не превращаются в зачёт новых уроков. Поле lessons хранит отдельные результаты предварительной теории; будущая версия должна отделить их от официально проверенного учебного прогресса.

**Статус: этап 4 ожидает одобрения заказчика и экспертной проверки материалов. Этап 5 не начат.**
